# Studio Consolidation Mocks (2026-11-13)

Static mocks for the merged Studio page — one working image, verbs acting on it, candidate strip + explicit save, no stacked sub-tabs. Palette/spacing follow the existing frontend (`#0f0f1a` family, purple accent `#5b4a8a`/`#b39ae0`). All data is fake; the working image is an inline SVG data-URI (no network fetches). Each page ≤900px stacks for iPad/mobile; Mock 4 also accepts `?stacked=1` to preview the stacked arrangement on desktop.

Serve: `python3 -m http.server 8840 --directory /home/zengonzo/workspace/ellieedit/mocks-studio-consolidation/`

- **mock-1.html — Canvas + Right Control Rail.** Image always visible on the left, all verbs in one docked right rail behind a single segmented control (Generate · Refine · Filters), with the save module pinned at the rail's foot. Tradeoff: highest form density without hiding the canvas, but the rail is tall and on narrow screens it drops below the canvas.
- **mock-2.html — Canvas + Bottom Sheet.** The image is pinned and dominant; verb panels live in a bottom sheet whose fixed header holds the candidate strip and whose footer holds run + save. Tradeoff: best image focus and an iPad-friendly touch zone at the bottom of the screen, but dense forms scroll inside the sheet — weakest on short laptop screens.
- **mock-3.html — Verb-Switched Workspace (rail left, Lightroom-style).** Tall verb modules on the left switch what the dedicated right-side viewer shows (comparer toggle in the viewer header); candidate strip spans the workspace bottom. Tradeoff: most familiar photo-app metaphor and room for verbose panels like full provenance, at the cost of an extra navigation layer and slightly less canvas width than mock-1.
- **mock-4.html — Immersive Stage + Floating Dock.** The whole page is the canvas; provenance chip, verb dock, transient flyout, candidate filmstrip and a save card float over it like camera chrome. Tradeoff: maximum image and the most "one coherent page" feel, but least conventional — floating chrome can overlap the image and long forms live in a flyout that must be opened deliberately (iPad portrait stacks via `stackmode`).
- **mock-1b.html — Rail v2 (refinement of mock-1).** Keeps mock-1's canvas + right rail and save module, with the confirmed §10 decisions applied: rail tabs are now Generate · Refine · Provenance (Filters demoted to a collapsible section inside Refine; Provenance shows filename/workflow/seed/steps/size/loras/denoise/prompt plus a parent-image chain with fake lineage). Adds an **immersive mode** (header toggle or ⛶ button): rail, banner, header and strip hide, the image fills the viewport, and only three floating controls remain — an always-visible left **edge tab** back to expanded, a circular **Generate FAB** bottom-right with a conic progress ring during fake runs, and a thin **bottom handle** that slides a transient candidate overlay up (contains the candidate strip plus save over/save new/Library; auto-dismisses ~3.5s after a run completes, tap-outside also closes). A completion **toast** flashes at the top on run end. The Generate panel gains a **batch-count drag controller**: four pips, drag or tap (pointer events, 44px+ touch row, min 1 / max 4, default 1); candidate strip and immersive overlay render that many candidates per fake run, with the "next run overwrites unretrieved candidates" caption present in both. No keyboard dependencies anywhere in immersive chrome.

Shared concepts across all four: provenance chip on the working image, candidate strip with "nothing auto-saves / next run overwrites" rule, three-target save module (save over · save new · save to Library), before/after comparer, and filters as an in-place toolset.
